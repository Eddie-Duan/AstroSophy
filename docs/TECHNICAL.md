# AstroSophy 技术与使用说明

## 应用能力

- Flutter/Dart Android 手机应用；相册选择、拍摄、星场检测、天区解算、测量展示均在设备内运行，不要求用户配置或维护自建服务器。
- 图片分析先缩放到最大边长 1200 px，再计算稳健背景、背景噪声、饱和比例和紧凑亮点；星点检测放在独立 isolate，避免阻塞 UI。
- 点源形态使用局部亮度加权二阶矩估计长短轴比；明显拉长的候选不参与恒星坐标匹配和 Gaia 标定测光，并提示其可能为拖线、失焦或处理伪影。单张图不能据此确认卫星或飞机。
- 首次启动显示整屏四页新手引导（导入星图 / 本机解析 / 看懂结果 / 保存回看）；各卡片的“？”可随时查看该指标的解释，顶部问号可以重播引导。
- 启动器图标与引导页吉祥物由 Recraft 在开发期生成矢量稿（前者渲染为 Android 多密度及自适应图标资源，后者栅格化为 PNG 后随应用分发）；Recraft 凭据不进入应用或仓库，见 [`tools/make_mascot.py`](../tools/make_mascot.py)。
- 图片选择支持常见图片和相机 RAW 文件。RAW 解码尝试在容器中查找最大的嵌入式 JPEG 预览；不同相机格式和厂商编码差异很大，因此不是完整 LibRaw 支持，也不是对传感器原始线性数据的分析。

## 本机天区解算

内置目录（`assets/catalog/`）由 [`tools/build_catalog.py`](../tools/build_catalog.py) 离线生成，幂等可重跑：Hipparcos 主表的 41,394 颗星（截至 V=8.0）连同 Bright Star Catalogue 的名称、[`lib/solver.dart`](../lib/solver.dart) 里的解算器全部在手机上运行。

解算分四步，全部离线：

1. **建索引**：为目录里每颗星找角距最近的若干邻居，两两三点组成三角形，用「次长边/最短边」和「最长边/最短边」两个比值当指纹——它们对平移、旋转、缩放、翻转都不敏感。
2. **取图内三角形**：从检出的星点里挑最亮的若干颗当种子，每颗同样取最近的若干邻居组三角形。
3. **粗匹配**：指纹对上即得到三点对应，据此解出「像素坐标 → 切平面坐标」的相似变换。
4. **验证精修**：把目录星投影回图像数内点，内点够多就接受，再用全部内点最小二乘，并迭代把切点挪到像面中心。

关键取舍是两边都按「最近邻居」而不是「最亮邻居」组三角形：最近邻居给出的三角形边长自动等于当地的星间距，所以图内和目录两侧的三角形尺度天然接近；换成最亮邻居，广角照片里最亮的星彼此隔十几度、窄视场里最亮的星都在视场外，两种极端都会让尺度对不上。

目录三角形的比值用球面角距算，图内三角形用像素距离算。两者在 TAN 投影下相差 O(θ²)，对几度视场只有万分之几，远小于指纹容差，省掉投影让建索引快得多。

**适用视场**：视场里大约要有 20 颗目录星才能稳定解算，对应视场直径约 4.5° 以上。更窄的望远镜视场会放弃本机解算，交给在线服务。

## 在线服务

- **Astrometry.net**：本机解算失败、且用户勾选授权后，把分析预览 JPEG 上传至 `nova.astrometry.net` 解算，轮询任务状态并取回 WCS。
- **Gaia DR3（ESA 归档 TAP）**：拿到 WCS 后查询视场内的恒星位置与 G 星等，用于标定星等零点和散布；用视场中心坐标，不上传照片。
- **SIMBAD（CDS TAP）**：按解算视场查询星名与深空天体，并在本地做坐标交叉匹配；没有手工枚举恒星清单。
- 低质量或无法解算的图片仍提供本地降级分析；不会在无坐标时猜测天体名称。

## 测量边界

1. **相对仪器星等**：本地检测星点的像素通量相对值，只能比较当前同一图像中的亮度，不是校准视星等。
2. **Gaia G 星等**：把 Gaia 星与 4 px 内的检出点源配对（要求置信度 ≥ 0.25、G 在 4–18 等之间），取星等差的中位数作零点，散布为 1.4826 × 中位绝对偏差；参考星少于 5 颗时不报告零点。设备光谱响应、白平衡、JPEG 曲线、饱和、镜头暗角等会带来系统误差，散布值不包含完整误差预算。
3. **孔径测光**：由全帧统计出的 PSF FWHM 决定孔径与天空环带半径，扣完天空背景后累加通量；星等误差只含光子噪声与天空背景估计误差，不含前述系统误差。
4. **天空背景视觉指数**：像素背景亮度归一化后的指标，受到曝光、ISO、白平衡和后期处理强烈影响，不是现场光污染测量，不能解释为 SQM 或 Bortle 等级。
5. **非星空掩膜**：用亮连通域面积、Sobel 梯度与行列方向的直线密度识别文字、表格、界面截图和大亮斑，掩膜内的像素不参与星点检测；结果给出非星空占比，占比过高时质量判为“较弱”并提示这可能不是纯星空照片。这是启发式判断，不是完备的内容分类器。
6. **质量提示**：由紧凑点源数、背景 MAD、饱和比例和局部点源形态生成；线状候选不是卫星/飞机分类器，也不是完整的云量或前景遮挡模型。
7. **用户剔除**：结果页可以把拉长的候选标为“非天体”。剔除项从星表匹配、测光、报告和模型摘要中排除，但仍留在图上和列表里（划掉显示），随时可以恢复。

## 隐私与联网

- API Key 使用 Android Keystore 支持的安全存储保存在当前设备；不会写入仓库文件。
- 照片默认不出设备：本机分析与本机天区解算都不联网。
- 可选 Astrometry.net 解算只有在用户勾选确认后才开始，并将分析预览 JPEG 上传至 `nova.astrometry.net`。请求设置 `publicly_visible=n`，但不能保证第三方数据留存或绝对保密。
- Gaia TAP 查询只发送解算得到的中心坐标和视场，不上传原始照片。
- 星名与深空天体目录查询发送视场坐标至 SIMBAD TAP 服务。
- 可选语言模型仅收到本地质量指标、天体名和测量摘要，不接收照片或 Key。模型 Key 会发送到用户输入的 Base URL；只应填写可信服务地址。
- 启用 Agent 需由用户自行在“本机 API 设置”填写 Key。DeepSeek、OpenAI、OpenRouter 和硅基流动模板仅预填 OpenAI 兼容 Base URL 与模型名，不内置 Key；模型名和接口支持可能变更，请以服务商控制台为准。自定义服务须兼容 `/chat/completions` 请求格式。
- 未启用解算或 Agent 时，图像读取、星点检测和画质诊断不需要网络。
- 演示星图（`assets/demo/`）由作者本人拍摄，提交前已裁掉画面底部的相机信息条——那一条里含拍摄地坐标。

## 保存与历史

- 存档写在应用私有目录下，一条记录由 `<id>.json`（测量结果与解算结果）和 `<id>.jpg`、`<id>_processed.jpg` 两张图组成，没有索引文件：目录本身就是唯一的事实来源。
- JSON 最后写入。写到一半掉电只会留下一个不会被列出的半截文件，不会出现“列表里有、点开是空的”这种情况。
- 存的是缩放到 1200 px 的预览图，不是原图——原图在用户自己的相册里。代价是从历史记录里重新解析时能测到的最暗星等会略浅，星点位置不受影响。
- 删除一条记录会连图片一起删掉；界面会显示历史记录占用的总空间。

## 代码结构

- `lib/main.dart`：入口、主题、主界面编排（选图 / 一键解析 / 结果页 / 保存退出）。
- `lib/analysis.dart`：图像解码、星点检测、孔径测光、非星空掩膜与分类、处理图生成。
- `lib/catalog.dart`：内置亮星目录与星座数据的加载和查询。
- `lib/solver.dart`：本机离线天区解算（三角形指纹匹配 → 相似变换 → 内点精修）。
- `lib/astrometry.dart`：Astrometry.net 上传与轮询，以及 Gaia DR3 / SIMBAD 查询。
- `lib/model.dart`：OpenAI 兼容模型服务的双模型路由。
- `lib/pipeline.dart`：一键解析流程与后台 isolate（`SkyWorker`）。
- `lib/report.dart`：爱好者报告（表格、直方图分箱、摘要与建议）。
- `lib/history.dart` / `lib/history_screen.dart`：存档读写与历史记录页。
- `lib/onboarding.dart` / `lib/widgets.dart` / `lib/theme.dart`：引导页、共享组件与配色。
- `tools/build_catalog.py`：离线生成星表与星座数据；`tools/make_mascot.py`：生成引导页吉祥物。
- `android/`：Android Manifest、应用入口和 Gradle 配置。
- `test/`：合成星场、测光、解算、报告、存档与界面测试。

## Android 启动与测试

1. 安装 Flutter stable SDK、Android Studio 和 Android SDK。
2. 运行 `flutter doctor`，接受 Android SDK licenses，并准备 Android 模拟器或开启 USB 调试的实体设备。
3. 在仓库根目录运行 `flutter pub get` 和 `flutter run`，或双击 `START.bat`。
4. 运行 `flutter test` 和 `flutter analyze` 执行项目验证；仓库的 GitHub Actions 会在每次推送时跑这两步、构建 debug APK，并把 APK 作为产物上传，保留 30 天。
5. 仓库中的 release APK 使用本机 Android debug keystore 签名，仅供个人设备安装；若有合法许可并另作分发，须按 Flutter Android 文档配置正式签名凭据。不要把 keystore 或密钥提交到 Git。

## 数据来源与致谢

内置目录与星座数据全部来自可再分发的公开星表，通过 CDS VizieR 取数，字段与来源记录在 `assets/catalog/catalog_meta.json`：

| 数据 | 目录 | 用途 |
| --- | --- | --- |
| Hipparcos 主表 | I/239（ESA 1997） | 位置与 V 星等 |
| Bright Star Catalogue 5th ed. | V/50（Hoffleit & Warren 1991） | Bayer/Flamsteed 名称、B-V、光谱型 |
| 星座边界 | VI/42（Roman 1987） | 判定恒星所属星座 |

星座连线不是抄自任何星图的现成画法，而是对每个星座最亮的成员跑最小生成树（按角距加权）自动生成的，因此不引入第三方星图数据的授权问题。

应用启动图标与引导页吉祥物插画由 [Recraft](https://www.recraft.ai/) 在开发期生成（矢量稿），凭据不进入应用或仓库。运行时用到的第三方服务是 [Astrometry.net](https://astrometry.net/)、[ESA Gaia 归档](https://gea.esac.esa.int/archive/) 与 [SIMBAD](https://simbad.cds.unistra.fr/)，均为可选功能，说明见上文“隐私与联网”。
