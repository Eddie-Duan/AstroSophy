# Feature list

[中文](./FEATURES.md) · [English](./FEATURES.en.md)

> Detailed feature list from the README. For UI strings, limits and data sources see [TECHNICAL.md](./TECHNICAL.md) (Chinese).

- **On-device analysis**: aperture photometry, point-spread-function (FWHM) estimation, background noise and sky-background index, saturated-pixel ratio — plus detection of text, tables and large bright blobs so they are not mistaken for stars.
- **Bilingual UI**: every string goes through one lookup table (`t()`) and can be switched at any time in Settings. The Chinese source text is the key, so a missing translation falls back to Chinese instead of showing a placeholder like `report.unresolved.label`. Translations are standard ARB files in `lib/l10n/app_<language>.arb` — adding a language means adding one file and re-running `tools/build_strings.py`, with no Dart changes. See "界面文字与多语言" in [TECHNICAL.md](./TECHNICAL.md).
- **On-device plate solving**: the app ships a catalogue (41,394 Hipparcos stars to V=8.0 plus a fallback layer of 1.206 million Gaia DR3 stars to G=11, about 10 MB) and uses triangle-fingerprint matching to solve the field centre and pixel scale. The catalogue is used in three tiers: the bright-star tier first, then the G<9 background stars, and only then the full layer. Fields wider than about 4.5° solve reliably on the bright tier; narrower fields use the background tier — down to the 1.5°–2.5° diagonal of a smart telescope. The limit is not the field size but whether enough catalogue stars are visible to cross-check each other.
- **Four analysis modes**: after picking a photo, choose On-device / Online / On-device first / Online first. On-device never uploads; Online goes straight to Astrometry.net; On-device first solves locally and uploads only on failure; Online first takes the online coordinates and then uses on-device ephemerides to add planets, comets, dwarf planets and asteroids. Online modes need a key and upload permission.
- **Online fallback**: only when an online mode is selected and the user explicitly agrees is the preview uploaded to Astrometry.net; the consent switch is off by default.
- **Shooting-scene prior**: an optional Automatic / Wide / Deep sky / Narrow field choice narrows the solver field range to what that kind of photo usually covers; Wide also skips the deepest index. Measured on M31: 5.7 s down to 2.1 s.
- **Crop before analysis**: after picking a photo, a crop frame selects the region to analyse. Only that region is analysed and, if necessary, uploaded. Watermarks and info bars burned in by the device can stay outside the frame — sent to the solver, they would be treated as stars.
- **Background solving**: a solve can take a minute or two, so the user does not have to wait. "Save and exit" releases the screen and returns to the app's start state while the solve continues in the background; the result is stored in the observation archive when it finishes, and the user can pick the next photo meanwhile. A banner on the home screen leads back to the running solve.
- **The progress bar changes colour**: mint green means the phone is computing; blue means the deepest catalogue tier is in use (with a "local deep thought" note at the left end); amber means the photo has been sent for online solving; **red means the local solve succeeded** — that red appears only when the photo never left the device, so no reading is required. A separate **silver-white with blue speckles** scheme appears when "analyse the Moon directly" is chosen: that run reports the Moon only and skips star detection and catalogue matching entirely.
- **The report says when a photo left the device**: if the solve came from Astrometry.net, the observation card on the result page gets an amber border and states up front that the analysis preview was uploaded and that coordinates and object names came from that service. Amber is the same colour used for "online" in the progress bar.
- **Nox assistant (optional)**: opened from the top-right of the main screen. It knows what the app can and cannot do, can read local observation records and the current photo's result, and can save, rename or delete records, request an online solve, or open pages on the user's behalf. Writes and network actions still ask for confirmation each time; the model cannot read arbitrary files, browse URLs or execute code.
- **Amateur-friendly report**: the report opens with "what you captured" — the constellation, bright stars with Chinese asterism names, and clusters and nebulae written as "catalogue number + Chinese common name" (`M 45 昴星团`, `NGC 6960 西面纱星云`), with object names coloured in the body text. The same object is written the same way on the image, in the list and in the report. A star catalogue, a magnitude histogram and a row of measurements follow. **Four target classes use four distinct markers**: bright stars are mint-green solid circles, deep-sky objects are pink solid circles (sized by the object's own angular size), planets and dwarf planets are amber dashed circles with a cross, and asteroids and comets are light-blue four-corner boxes with a cross. Dashes and boxes both say the same thing: this position was computed, not seen.
- **Lunar analysis**: photos dominated by the Moon are routed at the very start to a separate lunar pipeline and never enter star detection (on the lunar surface, "stars" are just craters and noise). It reports the disc centre and radius, the illuminated fraction, and — given the capture time — the phase name and whether it is waxing or waning. The illuminated fraction is computed two independent ways (pixel counting vs ephemeris) and shown side by side for cross-checking. Small moons are recognised too: even when the lit area is only 0.3% of the frame, the outer arc still gives the disc, without mistaking a small full circular streetlight for the Moon.
- **Interactive result page**: the top half is the annotated image, the bottom half a numbered list of the highlights in the frame; numbers match, and tapping an entry locates that object. The image can be pinch-zoomed and the circles scale with it. The list is grouped into **bright stars / highlights / suspect trails**, each collapsible, and whole groups of circles can be hidden or shown (bright stars only by default). Hiding draws nothing on the image — measurements, report and catalogue matches are unchanged. On-image labels avoid each other automatically.
- **Full-screen view, eraser and export**: the full-screen button opens the image at up to 12×; leaving full screen returns the split view to where it was. The full-screen eraser removes circles or labels with a tap and restores them on exit. Export redraws the **currently visible annotations** (hidden groups and collapsed stars included) on a 2400-px-long-edge canvas, with label sizes matching what the app shows, so the saved PNG is no longer small and blurry; the PNG goes to the system share sheet for saving to the gallery or a file.
- **Legacy Survey frame**: an entry below the capture-parameters table opens the DR10 survey viewer; the four photo corners are converted to RA/Dec through the WCS and passed as the viewer's poly parameter, so the photo frame is overlaid directly on the survey image.
- **Suspect trails are left to the user**: an elongated highlight may be a satellite, an aircraft, camera shake, or a star with a trailed image. Each entry has a ✓ / ✗ pair; ✗ removes it from photometry and the report while keeping it visible on the image and in the list, and it can be changed back at any time.
- **Solar-system bodies**: planets, dwarf planets, asteroids and comets form their own group in "targets in frame", right after deep-sky objects, and are **marked on the image by default**. The criterion is "no catalogue star at this position + the ephemeris puts it here" — both are required, so conclusions are always worded as "possible". The built-in tables cover 16 bright asteroids (Vesta is brightest at 6.5 mag; all ≤ 12.5 mag), 10 dwarf planets and all 939 comets. The object must be bright enough and not too close to the Sun (within 20° elongation it is only visible in twilight). A body in frame but too faint still gets a line — "it is here today at magnitude X, not capturable" — never silently omitted; but it is not marked on the image, because that would claim it was seen. About 80% of the comets' photometric parameters are defaults, so their brightness is worded as "possibly bright" without a number. The built-in tables carry a build date: measured positions drift 0.7′ in a year and 20′ in three, so the date belongs with the conclusion.
- **Constellation lines and all-sky map**: once the field is solved, constellation outlines and names in frame are overlaid on the image (online solves get them too), and a cross on an all-sky map shows which part of the sky the photo covers.
- **Agent (optional)**: query the current report, the bodies currently in frame (including solar-system bodies), where an asteroid or comet is now, a local observation summary or a single observation's details; it can also request saving, renaming or deleting an observation, an online solve, a visual mask, or open the history and settings pages. Every write or network action asks the user first. The number of tool calls is limited, and the model cannot read arbitrary files, browse URLs or execute code.
- **Visual mask**: the user can ask a vision-capable model to find watermark/text regions in the photo. Sending the image and applying the mask each require confirmation; the mask only affects on-device measurements and never modifies the original. Normal analysis does not upload images.
- **Save and revisit**: an observation and its measurements can be stored on the phone, then browsed, reopened, renamed and deleted. Each record is outlined in the colour of its result.
