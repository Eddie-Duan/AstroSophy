# 星表扩展建议：行星 / 彗星 / 小行星与 M·C·IC 深空天体

> 结论先行：目前星表**只有恒星**，本地链路只认点源，所以「动星」和「星云」都识别不出来。
> 本文给出根因定位与四档改进方案，按投入从小到大排列，明天可以按序开工。

---

## 一、现状核实

| 项目 | 事实 | 依据 |
| --- | --- | --- |
| 星表内容 | 41,394 颗**恒星**，V 星等 ≤ 8.0 | `assets/catalog/catalog_meta.json` |
| 数据来源 | Hipparcos `I/239/hip_main` + 亮星星表 `V/50/catalog` + 星座边界 `VI/42/data` | 同上 `sources` 字段 |
| 星座连线星等 | 4.6 | `catalog_meta.json` 的 `line_mag_limit` |
| 生成方式 | VizieR `asu-tsv` 取表，脚本自带 `--mag-limit` / `--line-mag-limit` 参数 | `tools/build_catalog.py` |
| 本地解算 | 三角形匹配，需 ≥ 4 个检出点源、足够内点 | `lib/solver.dart` |
| 检星方式 | 阈值图 + 连通域 + 集中度筛选，产出 FWHM / 轴比 | `lib/analysis.dart` |
| 拉长判定 | `axisRatio >= 2.2` 视为拉长（拖线），**被排除在解算之外** | `lib/models.dart`、`lib/solver.dart` |
| 在线链路 | astrometry.net 解算 → Gaia DR3 定位 → SIMBAD 取名与分类 | `lib/astrometry.dart` |
| 深空天体 | 在线时靠 SIMBAD 的 `isDeepSky` 标出，但只画位置不参与本地解算 | `lib/astrometry.dart` |
| 拍摄时间 | `CaptureMetadata.timestamp` 字段已定义，但**从未被填充**（选图时 `requestFullMetadata: false`） | `lib/models.dart`、`lib/main.dart` |

### 四个具体缺口

1. **星表无深空天体**：M31 这类目标在 `stars.json` 里不存在，本地永远标不出名字。
2. **星表太浅（≤ 8.0 等）**：窄视场拍星云/行星时，画面里 ≤ 8 等的恒星屈指可数，
   `solver.dart` 的三角形匹配凑不出足够候选 → 本地解算失败，只能回退在线。
3. **只认点源**：星云是弥漫结构，集中度低，多数进不了 `DetectedStar` 候选；
   即便进了，解算也只用非拉长的点源。
4. **没有时间维度**：行星/彗星/小行星的位置随日期变化，必须结合拍摄时刻查星历才可识别；
   而现在连时间都没读出来。

### 已经做对的部分（要保留）

- 在线链路里 SIMBAD 的 `otype` 分类已覆盖星系、星团、星云、HII 区、SNR；
- 深空天体是**按目录坐标直接换算像素**，不依赖点源检出，所以标位置本身是可靠的；
- 链路的降级设计（`pipeline.dart` 的 `warnings`）允许某一环失败而整体不中断。

## 二、改进方案

### A. 快速见效（不改数据，约 1–2 天）

| 编号 | 改动 | 涉及文件 | 验收 |
| --- | --- | --- | --- |
| A1 | 让弥散/略拉长的亮源也能进入解算候选：单独放宽用于解算的轴比与集中度门槛，而不是全局改 `isElongated` | `lib/analysis.dart`、`lib/solver.dart` | 用 `assets/demo/demo_m31.jpg` 本地解算成功率上升 |
| A2 | 解算失败时给可操作提示（开在线解算 / 补拍摄时间 / 换宽场），而不是只说「星点不足」 | `lib/pipeline.dart`、`lib/main.dart` | 失败路径的 `warnings` 文案可执行 |
| A3 | 把在线已识别到的深空天体渲染成「M31 · 旋涡星系」并写入报告，而非只画一个点 | `lib/astrometry.dart`、`lib/report.dart`、`lib/widgets.dart` | 报告出现「画面中的深空天体」条目 |

> A1 要注意：放宽门槛会引入更多假点源，必须同时保留「解算候选」与「展示用检出」两套过滤条件，
> 否则界面会被伪星点刷屏。

### B. 星表扩容（解决窄场解算率，约 3–5 天）

- 用 **Gaia DR3**（G ≤ 12–14）做稀疏抽样替换/补充 Hipparcos，让窄视场也有足够参考星。
  - 抽样策略建议按天区均匀抽样，控制体积（目标 ≤ 3–4 MB），
    沿用 `catalog.dart` 现有的赤经赤纬分格索引结构，避免改查询逻辑。
- 打包流程直接扩展 `tools/build_catalog.py`：新增数据源 + `--gaia-mag-limit` 参数，
  输出仍写回 `assets/catalog/`，`catalog_meta.json` 增加新来源说明。
- 风险：Gaia 无 BSC5 那样的传统星名，`names.json` 的命名覆盖不会变好，需要另配亮星名表。

**建议顺序上把 B 放在 C 之后**：C 不依赖网络也不依赖大体积资源，收益立即可见；
B 影响的是资源体积与解算耗时，需要单独做性能回归。

### C. 离线深空天体目录（离线也能标 M / C / IC，约 3–5 天）

1. 打包精简 DSO 目录：Messier 110 + NGC/IC 主要成员，
   字段取「主名、RA、Dec、类型、角尺寸、视星等」，约几千条、几十 KB。
2. 新增加载器（可与 `catalog.dart` 共用分格索引思路），在**本地解算成功后**、
   未走在线链路时也能做坐标 → 像素换算并标注。
3. 报告新增「画面中的深空天体」段落：名称、类型、角尺寸，并与用户像场尺寸对比，
   说明「这个目标占画面多大比例」。
4. 反向提示：命中 DSO 时，明确告诉用户「这是一张深空目标照片，星点稀疏属正常」，
   避免用户误判为失败。

### D. 太阳系运动天体（行星 / 彗星 / 小行星，约 1–2 周）

前置工作（必须先做）：

- 打开图片元信息读取：`lib/main.dart` 的 `pickImage` 改为 `requestFullMetadata: true`，
  并实现 EXIF `DateTimeOriginal` 的解析，写入 `CaptureMetadata.timestamp`。
  （注意：入库演示图已裁掉信息条，不影响。）

识别流程：

1. 用已有的 WCS + 拍摄时刻算目标视位置；
2. 与检出点源对照，命中容差内则标为「疑似行星/彗星/小行星」；
3. 判定规则写进报告：**星表里查不到对应恒星 + 位置与星历吻合**，两条同时满足才下结论。

数据来源两条路，建议先离线后在线：

| 路线 | 内容 | 优点 | 代价 |
| --- | --- | --- | --- |
| 离线 | 行星用截断 VSOP87；亮小行星/彗星用 MPC 轨道要素（固定少量目标） | 无网络、无授权、可离线 | 精度中等，需要内置要素表 |
| 在线 | JPL Horizons / MPC 接口 | 精度高 | 依赖网络与授权，隐私上要经用户同意 |

**A1/A2/A3 完成后再做 D**：D 依赖可靠的 WCS 与时间，两者任一不可靠都会给出错误结论。

## 四、风险清单

1. **假点源**：放宽检星门槛会引入噪声，必须分离「解算候选」与「展示检出」两套判据。
2. **资源体积**：Gaia 抽样若不控量，会显著增大安装包与首次加载时间。
3. **错误断言**：行星识别一旦时间或坐标错位就会给出错误结论，
   必须同时要求「星表无对应恒星」与「星历吻合」，并在报告中保留不确定度说明。
4. **隐私**：EXIF 含时间，在线星历查询涉及上传；需沿用现有「用户授权后才联网」的约定。
5. **既有测试**：`test/` 下已有 `solver_test.dart`、`photometry_test.dart` 等，
   每次改动后应跑最小相关用例，避免破坏现有行为。
