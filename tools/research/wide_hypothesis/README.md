# 宽视场「图形 → 天区」可行性基准

这是为「80°+ 手机星野能不能用一个小模型先粗定位」做的前置实验，**结果是否定的方向，不进 App 运行时**。App 里本机解算仍以相似变换为主，超广角照片走在线解算（在线结果现在会读 SIP 曲率，见 0.5.6）。

## 问题

本机解算的三角形指纹要求两侧用同一套近邻关系。宽视场照片里，画面中心 10° 内的亮星三角形，和星表的近邻集合平均只有约三成重合（图里检出到约 6 等，星表 V≤6 的密度对不上），粗解全部落在随机水平。于是想：能不能用「星点组成的图形」直接查天区？

## 实验

`bench.py` 只测「图形本身有没有可检索的天区信息」，不训练网络：

1. 用内置 Hipparcos 星表合成针孔像面上的星点图形：随机天区、50–90° 对角线视场、随机滚转/镜像、随机曝光极限 5–7 等、0.35 等测光噪声、8% 误检；
2. 描述子取旋转/平移/缩放/镜像都不变的量：最亮 12 颗星的**排序后两两距离**（归一化）＋排序后的星等差。这是最稳的手工不变量，避开了「按亮度排序做参考系」在测光噪声下翻转的问题；
3. 另一批随机样本当查询，看最近邻 Top-K 能不能把天区找回来。

### 结果（2026-11-07）

| 数据 | Top-200 里离真值最近（≤5° 比例） |
| --- | --- |
| 合成验证集（2000 条） | **83.6%** |
| 真实 83° 手机照片 | **12.2°**（不在 5° 内） |

## 结论

- 合成数据上「图形 → 天区」确实能把范围缩到几度，说明**信息是有的**；
- 换到真实照片就退化到 12°：瓶颈不是搜索量，而是描述子的域差距（哪 12 颗被选中、测光排序、误检、投影）；
- 因此「一块星点图形 → 一个天区」不能直接作为交付，最多是**假设生成器**；验收必须仍旧交给几何拟合（SIP 曲率 + 内点概率，`lib/distortion.dart`）。

## 下一步（按优先级）

1. **换描述子**：把「排序后的距离多重集」换成保留点对应关系的结构（四点几何哈希、或图网络 DeepSets/PointNet 的端到端表示），并把描述子训练目标改成「先检索、再由几何验证打分」的对比学习；
2. **域对齐**：用真实手机照片（含已知 WCS 的）微调；曝光极限、误检率按实测分布采样；
3. **别把模型当答案**：模型只给 Top-K 假设，几何验证（中心亮星 Procrustes 粗配 + SIP 拟合 + 内点概率）决定最终解；
4. 若合成 recall 上不去，就回到确定性路线：手机姿态（IMU/EXIF 焦距）给一个几十度的先验，再用曲率模型解算，不引入模型。

## 运行

```bash
python tools/research/wide_hypothesis/bench.py
```

依赖：`numpy`；读 `assets/catalog/stars.json`，可选读 `build/repro/detections.csv`（真实照片的检出表，不在仓库里）。
